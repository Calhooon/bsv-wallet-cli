- **`reconcile-outputs` and the respend's settle read a stored transaction only when its bytes hash to its txid (#660, the audit of every mark that takes a coin out of offer).** A stored row whose bytes are not the transaction it is stored under is skipped: `reconcile-outputs --execute` re-links no coin to it, and the respend's settle settles nothing for it and logs why. Before, each could lock a free coin to such a row; neither could lose one. An ordinary store holds no such row and sees no change. The other commands that mark a coin spent by another transaction (`cleanup-abandoned`, `reconcile-outputs`' second phase, `sync --reconcile-spent`) already move a coin only when the spender's own bytes hash to the txid that was proven, spend that outpoint, and the proof's root is one this wallet's headers carry; each now has a test of it.
