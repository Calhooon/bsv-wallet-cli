- **`reconcile-outputs` and the respend's settle read a stored transaction only when its bytes hash to its txid (#660, the audit of every mark that takes a coin out of offer).** A stored row whose bytes are not the transaction it is stored under is skipped: `reconcile-outputs --execute` re-links no coin to it, and the respend's settle settles nothing for it and logs why. An ordinary store holds no such row and sees no change. The other commands that mark a coin spent by another transaction (`cleanup-abandoned`, `reconcile-outputs`' second phase, `sync --reconcile-spent`) ask the wallet library, which names a spender only when the spender's own bytes hash to its txid, spend that outpoint, and its proof's root is one this wallet's headers carry; each command now has a test that it moves a coin on that answer alone and on nothing less (an unknown, a spender not yet proven, a fault).
