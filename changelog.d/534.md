- **A page that reconnects within ten seconds resumes its prompt (#534)**: when a page held on the owner's answer closes its connection (a reload, a dropped network, a fetch it aborts and sends again), its pending request now waits `ABANDON_WINDOW` (10 s) for the page to ask again; a call of the same site (any port of its host) asking the same power inside the window is held on the same request, the same id, and the owner's later answer answers it once. Past the window the disconnect's deny runs as before: the request is withdrawn and every call still held on it is answered 400 `Permission denied.`. A spending request is withdrawn at once, as before. An abandoned request holds its place under the cap of held calls, and the call that resumes it takes that place over. The listings show the state: `abandonedAt` and `abandonedUntil` (the window's end) in a pending row's JSON while it waits, and `caller disconnected, withdrawn at <time> unless the page asks again` on the CLI's line and the inspector's row, whose answer buttons are disabled meanwhile.
- **The owner's answer to a request waiting for its page is refused, 409 `CONFLICT` (#534)**: `pending request #N is waiting for its page to reconnect; answer it when the page asks again, or it is withdrawn at <time>`, from `POST /origins/answer`, the MCP's `answer_origin`, the inspector, and `bsv-wallet origin-grant` and `origin-deny` (exit 1). No grant is written for a page that has left; answer the request again once the page asks again.
- **The store's pending table gains `abandoned_at` (#534)**: a store of the previous shape is rebuilt once, at the first open, under the writer's lock, every row and the table's id sequence carried.
