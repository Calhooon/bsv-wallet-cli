- **The beta.8 pin (#565): bsv-rs =0.9.0-beta.8, bsv-wallet-toolbox-rs =0.14.0-beta.8, bsv-tracker =0.9.0-beta.8, together.** Each package was read at the commit its tag names (bsv-rs `31a6ccf0`, the toolbox `fc9c54a4`, the tracker `3adda346`). The locks gain `argon2` 0.5.3 and `blake2` 0.10.6, from the toolbox's CWI key file; no feature of this crate is lost.
- **bsv-rs #817 (the BEEF and merkle path writers, `merge_raw_tx` and `merge_beef` return `Result`):** each production site carries the error. The tracker's two stored-path sweeps read a stored path the writer refuses as no bump. `receive`'s BananaBlocks courier treats a proof that does not write as a BEEF as the rung's fault, and the next courier is asked.
- **bsv-rs #843 (`Transaction`'s fields are private):** reads go through `inputs()` and `outputs()`. `respend`'s one write goes through `outputs_mut()`. No answer moves.
- **`internalizeAction` answers in the toolbox's beta.8 words and rules.**
  - A BEEF that carries a payment output and cannot be read is refused with `Cannot read the BEEF's subject transaction to check payment outputs: ..`.
  - A payment output that is not the P2PKH of its derived key is refused.
  - A basket insertion into the default basket is refused. So is one that reclassifies wallet-managed change, or one that moves an output between application baskets. Each is 400 `VALIDATION_ERROR`, by class.
- **`createAction` on a coin whose stored bytes are not one transaction** answers the BEEF error, 400 `ERROR`. Beta.6 skipped the coin, or named it `UnspendableCoin` (409). The toolbox's coin-gap reader classes only a missing transaction as a gap (#611).
- **#557 stays held.** The toolbox still wraps internalize's header fault as a `ServiceError` text (`beef_verification.rs:49`). `AbortAcceptance.kind` is left `Other` by the toolbox, so the abort's class is read as before.
- **The security carry: bsv-rs 0.9.0-beta.8 carries sixteen published advisories.** These doors of ours now refuse what beta.6 accepted:
  - `gift-claim` and `gift-inspect` refuse a deposit whose bytes run past the transaction (GHSA-67vc).
  - The readers of stored and fetched transactions refuse trailing bytes and amounts of 2^53 or more (GHSA-j8hr, #844).
  - `certificates --reverify` fails a certificate whose signature is not exact DER (GHSA-9c8r).
  - `/internalizeAction` refuses a BEEF with a raw entry that is not a transaction (GHSA-j8hr), and a spend its coin's era refuses (GHSA-h4m7, GHSA-fr33).
  - `/acquireCertificate` by issuance refuses a certifier's response with trailing bytes (GHSA-cgp9).
  - GHSA-82g9 has no patched version; no Rust code here, in the toolbox or in the tracker reads Extended Format.
