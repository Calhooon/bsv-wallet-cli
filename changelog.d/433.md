- **API change: the browser gate's allow-list constructors return the rule a bad entry breaks instead of panicking (#433).** `server::AllowedOrigins::new`, `server::ServerConfig::admitting` and `server::ServerConfig::from_config` now return `Result<_, server::OriginatorRule>` (also `config::originator::OriginatorRule`; its `entry()` and `rule()`, one of `config::originator::SCHEME`, `PARTS` or `NAME`, and its text the binary's own refusal of that entry in `ALLOWED_ORIGINS`; it converts to a `config::ConfigError`). A crate consumer that builds the server in-process with an entry such as `http://localhost` gets the error instead of a panic at startup; `config::originator::listed` checks one entry the same way. The binary's refusal of a bad `ALLOWED_ORIGINS` entry is unchanged in text and exit code (1), now pinned by `tests/allowed_origins_refusal.rs`.
