- **A testnet wallet made by an earlier release is repaired with `repair-chain`, on its own evidence (#682).** Every release before 0.19.0-beta.4 wrote a `--testnet` store's chain word as mainnet's, and since the chain word's check such a store is refused when opened with `--testnet`. The refusal for that case now says not to run the wallet without `--testnet` and names the repair. `bsv-wallet [--testnet] repair-chain [--execute] [--unchecked] [--json]` sets the store's chain word to the command's chain. It builds no wallet and asks no service but the header service (`CHAINTRACKS_URL`). Its evidence is the store's newest stored proofs (three at most) against the header at each proof's height: `agrees`, `disagrees`, or `none` (no proof, `CHAINTRACKS_URL=off`, or a header that could not be read). It is a dry run by default. `--execute` writes the word when the evidence agrees, when it is `none` only with `--unchecked` as well (the report says it wrote with no evidence), and never when it disagrees (the heights are named and nothing is written). A word that is already right is said and nothing is written. `init` over an existing store of the other chain is now refused by the same check before anything is written, and `bsv-wallet ui` refuses such a store before it serves a page. No served answer moves.

  What an operator of a testnet wallet does at the upgrade:
  stop the wallet and run `bsv-wallet --testnet repair-chain` (with your `--db` if you use one) to see the stored word and the evidence;
  when it agrees, run it again with `--execute`; when there is none (no mined proof yet), with `--execute --unchecked`; when it disagrees, write nothing and check which chain the coins are on;
  then start the wallet with `--testnet` as before, and never run a testnet wallet without the flag.
