- **The per-origin grants' store, internal (#414, the design's L1):** a new library module, `store::origin_grants`, owns three tables beside the toolbox's in the wallet's SQLite (`origin_grants`, `origin_pending`, `origin_spends`), their `ensure` (it reads `sqlite_master` first and creates whatever is missing in one transaction, touching none of the toolbox's tables) and the row functions the design names: the lookup (live, revoked, none, expired; `0` never expires), a pending row opened or joined, the answer given once, the grant upsert, the revoke stamp, the fold of `ALLOWED_ORIGINS` entries into `source` `env` rows (a revoked row is never granted again) and the month's spending tally. No behaviour change: nothing calls the module yet, so no wallet's file gains the tables, and the browser gate still reads `ALLOWED_ORIGINS`.
