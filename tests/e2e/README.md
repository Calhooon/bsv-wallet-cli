# E2E harness

Run the 25 scenarios with `E2E_HERMETIC=1 NODE_USE_ENV_PROXY=1 node tests/e2e/run.js` using Node 24 and the release wallet and MCP binaries. Set `BSV_WALLET_BIN` and `BSV_WALLET_MCP_BIN` to binaries outside the checkout, and `E2E_WALLET_TMP` to the run's scratch directory. The [hermetic guide](../../docs/E2E-HERMETIC.md) describes the local stub, proxy wall and cleanup; [CLAUDE.md](../../CLAUDE.md#e2e-funder-wallet) describes the separately operated mainnet funder.

The CLI judges no transaction itself; internalize verification belongs to the toolbox, with the node's word per input on the toolbox's lane ([toolbox #422](https://github.com/Calhooon/bsv-wallet-toolbox-rs/issues/422)).

E2E.24 keeps a 15,000-sat funder-owned coin in the `e2e-external` basket: `e2e` names the harness and `external` names its role as an external input to A's unsigned template. When that basket has no spendable 15,000-sat coin, the existing funding transfer to A carries one additional output to the funder's own locking script with `basket: 'e2e-external'`. Later runs reuse the coin without adding an output. The hermetic funder follows the same path. No scenario signs, spends or sweeps this coin. Toolbox `0.14.0-beta.2` selects the default basket in `src/storage/sqlx/create_action/mod.rs:150`, passes its ID to the count at `mod.rs:333-340`, and filters both count and funding selection by `o.basket_id` in `allocation.rs:77-79,388-410`; a named basket is outside ordinary funding and change allocation. Funder accounting includes both baskets, so reserving the coin does not count as spending against the unchanged 5,000-sat run cost cap (#336).

Design (c) remains: E2E.24 temporarily sets fresh wallet A's default basket's desired change count to one for the kept unsigned template, then restores it in `finally` before the WAL writer. The runtime query reads A's basket minimum and eligible change count, giving `demand = 1,000 + max(1, floor(minimum / 4)) + 23 + 500`, or 4,023 sats at the default 10,000-sat minimum for any available count, including zero. The scenario prefers the `e2e-external` coin and reads its BEEF with `listOutputs` and `include: 'entire transactions'` on that basket. Only a missing coin permits fallback to the default basket's largest coin, with a printed `WARNING #336`. The demand line names the source basket, coin and margin and requires at least 10,000 sats of margin; the reserved coin leaves 10,977 sats at the default minimum. Cleanup aborts the unsigned template and the run checks that the same coin survives the sweeps.
