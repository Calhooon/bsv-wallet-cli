# Architecture rules as tests (#73)

Eight rules of where things may live in the shipped code, each a test under `tests/arch_*.rs` in the shape of `tests/rule_28_sites.rs`: a scan of the crate's own `src/` with an allowlist. Each allowlist names today's sites by file, with a count and a reason, so a rule passes on `beta` and refuses any new site. A count is exact: a file over its count fails with every line it holds, a file under it fails until the entry is lowered (or removed at zero) in the same PR. An allowlist only shrinks: the scoreboard's `--check` against the base (the ratchet job, #77) refuses a count above the base's, so a new site goes to the rule's home or the PR does not land.

`cargo test --locked` runs them; one rule alone: `cargo test --locked --test arch_no_unwrap`.

## What is scanned

`tests/arch_support/mod.rs`, shared by the eight. Every `.rs` file under `src/`, minus test code: every item a `#[cfg(test)]` attribute carries (a `mod tests { .. }` block, a function, a statement, a field, a variant, a match arm) and every file that is test code whole, as `tools/ratchet`'s `test_files` reads it: a file under the crate's top-level `tests/`, `benches/` or `fuzz/`; a file a `#[cfg(test)] mod x;` declares (`x.rs` or `x/mod.rs`, or its `#[path]`); a file a plain `mod y;` declares inside a file that is already test code; and every file under such a module's directory; iterated until nothing grows. A file's name decides nothing. Today: `src/test_support.rs` and `src/test_support/tx.rs`, `src/tracker_words_witnesses.rs`, `src/chain_feed_tests.rs`, `src/spend_gate/tests.rs`, `src/server/handlers/tests.rs`. All of it is read from the comment-blanked text, so an attribute spelled in a comment or a string literal carries nothing and declares nothing. Comments are never read. The env, unwrap, spawn, prefix and error-words rules count calls with string and char literals blanked; the SQL and explorer rules read string literals. A call is counted by its name at an identifier boundary: `x.unwrap(`, `Option::unwrap(` and a bare `unwrap(` after a `use` each count once; a longer name (`my_unwrap(`) and a definition (`fn unwrap(`) do not. Each rule file is data: a `Rule` (its message, its homes, its allowlist and the sites it counts on a line) that `Rule::check` runs. The five scanner tests of `tests/arch_no_unwrap.rs` (`the_scan_reads_only_the_shipped_code`, `a_test_member_ends_at_its_own_end`, `a_call_is_its_name_at_a_boundary`, `test_files_are_declared_in_code`, `a_test_modules_children_are_test_code`) pin the scanner. The crate root is cargo's `CARGO_MANIFEST_DIR` at run time, so a test binary reused from a shared target dir scans the checkout it runs in.

Not scanned: `mcp/` (its own crate) and `tests/`.

## Notes

- A4's count is 4 (9 until #85 removed four: drain, send, split, the server's ctrl-c; 5 until #80 read the relay's default address as a typed constant) where the 2026-10-23 brief counted 97. A text count that stops only at `#[cfg(test)] mod tests` gave 102 on the tree the rule was written on: it reads the `pub(crate) mod tests` bodies of `src/tracker_host.rs` (74) and `src/commands/receive.rs` (17), and the second test module of `src/server/mod.rs` (2), all test code. The brief's 97 is not reproduced here.
- A2 counts statements, so a subquery's `SELECT` counts too; a reflow of a statement does not change its count.
- The retire guard's proof read (#244) is the store's `stored_proof`, so A2's count did not move.
- A5 is a text rule: it cannot tell an error message from another string, so its allowlist says which each site is. A typed error removed the need in the served layer (#81); the one error site left is `src/toolbox_words.rs`, where the toolbox's `From<Error> for bsv_rs::Error` (=0.13.0) has erased a refusal's variant to a `WalletError`'s text before this crate sees it.
- A8 reads a receiver by its name, so it is scoped to the served layer, where the error's text has those names; `the_counter_sees_an_error_read_by_its_words` plants `AppError::classify`'s old lines (counted) and the layer's other string tests (the `Bearer ` strip, a code-unit range, a content type, a door list, a txid search; not counted).
- Known limits, where a grep cannot say the rule and a dylint would (#73): a name reached through an alias is one site at its `use` and none at its calls (`use std::env::var as v;` then `v("X")`); a module alias is seen at its calls (`e::var(`); a name passed as a value is not seen (`.map(env::var)`, `.map(Option::unwrap)`); a spawn through a helper (`spawn_served_loop` is one site, its callers none); an SQL statement built from pieces or opening with a word outside the list (`WITH`, `REPLACE`); an explorer named in pieces or read from a setting; an error's text bound to another name before A8's test (`let s = e.to_string(); s.contains(..)`); a prefix test written another way (`&s[..n] == ".."`, `trim_start_matches`, `split_once`; `lowercase_split_key` in `src/tracker_host.rs` uses a checked slice equality for an identifier because A5's grep counts prefix methods and its allowlist ceiling only shrinks); a test gate that is not `#[cfg(test)]` exactly (`#[cfg(all(test, ..))]`), whose item is counted as shipped code (the loud side).
