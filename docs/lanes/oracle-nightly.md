# Lane oracle-nightly: mutation testing and fuzz targets on a schedule (#75, #76)

**Repository.** `bsv-wallet-cli`, your worktree on a branch from `origin/beta`. `docs/lanes/README.md` binds you. Three hours.

**Read in this order.** #75, #76 and the epic #106. `~/bsv/bsv-rs/fuzz/` (the house's one fuzz target: its manifest and its shape), `src/server/types.rs` (the served bodies), `src/server/handlers.rs` `internalize_args` and the BEEF handling in `create_action` and `internalize_action`, `src/explorers.rs` (the explorer response parsers), `src/spend_gate.rs` `AllowPending::from_json` and `parse_outpoint`. `~/bsv/bsv-stack-lean/docs/charters/beef-of-any-size.md` for what a reader must refuse.

**The work.**
1. `fuzz/` with `cargo-fuzz` and its own manifest (outside the workspace; the root `Cargo.toml` untouched): targets `beef_reader` (the AtomicBEEF and BEEF bytes the server consumes, through the same calls the handlers make), `brc29_remittance` (the internalize arguments: remittance, derivation prefix and suffix, output index), `served_json` (the createAction and internalizeAction request bodies through serde into the handler's argument mapping, no store), `explorer_bodies` (each provider's parser in `src/explorers.rs` on arbitrary bytes), `allow_pending` (`AllowPending::from_json`, `parse_outpoint`). A seed corpus under `fuzz/corpus/<target>/` from the fixtures the tree already has (the vectors, the e2e recordings if any exist in `tests/`).
2. `.github/workflows/nightly.yml`: a schedule (03:00Z) and `workflow_dispatch`; a job per fuzz target running one hour with the corpus checked in and new corpus entries committed back by a PR the job opens (or uploaded as an artifact if a PR from a workflow is refused; say which); a `mutants` job running `cargo-mutants` over `src/spend_gate.rs`, `src/tracker_host.rs`, `src/server/handlers.rs`, `src/broadcast_verify.rs`, `src/explorers.rs` with `--in-place` off and a timeout per mutant, publishing the score per file as a job summary and failing below 80 percent on those files (record the first run's scores in the report; if any file is below 80 today, the floor is that file's score rounded down, named in the workflow with the issue to raise it).
3. `docs/NIGHTLY.md`: what runs, where the results land, what a crash input becomes (an issue with the input attached), what a surviving mutant becomes.

**Bounds.** Do not run the fuzz targets for more than ten minutes each locally; the hour is the schedule's. `ci.yml` untouched (the nightly is its own file). No edit under `src/` except a `pub` a target needs, named in the report. If `cargo-mutants` on this tree needs more than the lane's hours for its first full run, run it on `src/spend_gate.rs` alone and report the rest as `[D]`.

**Report.** `REPORT: STATUS done|blocked`, the base and tip commits, each target's local run (minutes, executions, crashes), the mutants score per file, the commands and their tails, the six tests each choice passes.
