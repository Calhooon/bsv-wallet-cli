# Lanes of the north-star programme (epic #106)

A lane is one issue of the programme, worked in its own worktree on a branch from `origin/beta`, landed by the captain through a PR into `beta`. The briefs here are the records of what each lane was asked; the lane's report is its reply. The shared rules, which every brief assumes:

1. **Where you work.** The worktree cca gives you, on a branch from `origin/beta` (never `main`; `main` is the stable line). `CARGO_TARGET_DIR` under `~/bsv/targets/` or `/Volumes/Lanes/targets/`, never inside the checkout and never `/tmp`. Never the repository's own checkout, never `e2e-funder/`, never a secrets file, never `~/vault/`.
2. **The proof rule.** Every claim with its command and the last lines of its output in the report. A test you did not run is not a test. `[X]` run, `[D]` told.
3. **No network except reads.** No sats move, ever; the mainnet e2e gate is the captain's and runs once per release. The funder daemon on :3320 and every port of `~/bsv/prod-test-wallets/REGISTRY.md` are not yours.
4. **The references, at pins.** BRC-100 and the wallet BRCs at `~/bsv/brcs` (`git show upstream/master:wallet/0100.md`, the commit named in #100); the stack's wallet charter and Lean definition at `~/bsv/bsv-stack-lean/docs/charters/wallet.md` and `lean/Wallet.lean`; the stack's lane rules `docs/lanes/l2-README.md` (the six tests T1 to T6, which your report names for each design choice); the node's harness as the pattern for ours, `~/bsv/bsv-script-lean/harness/README.md` (the evaluator is the oracle, the corpus is the judge). Read with `git show <pin>:<path>`, never a working tree.
5. **One concern per PR.** A refactor never carries a behavior change; a behavior change changes its fixture in its own commit. The gate: `cargo fmt --all -- --check`, `cargo clippy --all-targets --locked`, `cargo test --locked`, `cargo deny --locked check advisories`, green before the report. A lane that edits `tools/ratchet` or `tools/ratchet.d/clippy.toml` re-records `docs/ratchets.json` in its own commit after the tool's, in the same PR, with the reason in its message and renders `docs/NORTH-STAR.md`'s table in that commit (`python3 -B tools/scoreboard --render`; the table is rendered from the record, #361): the record carries the tool's fingerprint and `tools/ratchet --check` refuses a record another tool made (#127).
6. **Wording.** No em dash. Never "first", never "conformant" without a run. No hostname of a deployment, no token shape, no account id.
7. **The report.** First line `REPORT: STATUS done|blocked`, then the base commit, your tip commit, the files, the commands and their tails, what is `[D]`, what you did not run and why, and what the captain must do at landing. Stop and say so when a step needs a word that is not yours. After the STATUS line and the proofs, every REPORT ends in the bounded form: `DECISION:` one line; `CONFIDENCE:` a number in [0,1]; `RISKS:` each residual risk on its own line with its own score in [0,1] (`RISKS: none` allowed); `RATIONALE:` at most five lines. A review's REPORT opens its form with `VERDICT merge|fix`. When several readers or reviewers answer one question, [ENSEMBLE.md](ENSEMBLE.md) is the rule: a consensus is an agreement fraction of at least two thirds AND a mean confidence at or above 0.7 on the EXACT mean, with at least two readers; one reader is never a consensus.
8. **Bounds.** The brief's hours are the limit; past them, `STATUS blocked` with what remains.
9. **Foreground only.** Every build, test and measurement runs in the foreground of your own turn; never hand work to a background job or a watcher and never end your turn while work is pending. A lane that ends without its commit and its REPORT has failed, and the captain relaunches it (2026-10-23: three lanes ended "waiting for load" or "waiting on background jobs" with their edits uncommitted). If a machine is loaded, measure anyway and say so; a quiet re-measure is its own commit later.
10. **The SDK on this Mac.** If linking fails under the macOS 27 SDK ("tapi error"), set `SDKROOT` to the MacOSX26.5 SDK for your commands and say so in the report; it is a host fault, not the repo's.
11. **A refactor's differential.** A refactor lane's REPORT carries the `DIFFERENTIAL:` line of `tools/differential` run against its base, with zero differences (docs/DIFFERENTIAL.md); a lane cannot mark a refactor done without it, its PR carries the label `refactor`, and its cold review runs the differential itself (since 2026-10-27 CI's differential runs on dispatch and before a tag, never on a PR: the owner's word). Two runs may share a machine: `tools/differential` owns per-run worktrees, output directories and ports, and no private `TMPDIR` is needed, except that scenario 20's inspector UI keeps the harness's fixed port 9321, which the tool does not choose: two runs whose scenario 20 overlap fail closed (exit 2), so stagger them. Each run uses its own head `CARGO_TARGET_DIR`; shared base builds are locked through copying both binaries into the run's output directory, and recordings use those copies. Until bsv-wallet-toolbox-rs #105 (the coin tie) is pinned, zero cannot be met reliably (two runs of one binary can differ from scenario 22 on): the REPORT carries the floor pair's line (`--same` on the head) beside its own, and a difference the floor does not show is the refactor's. The CI job's refactor failure is held until then (`REFACTOR_FAILS` in ci.yml, one line).
12. **A changelog fragment per change.** Add one file in `changelog.d/`, named `<number>.md` or `<number>-<slug>.md`, where the number is the issue, or the PR when there is no issue. Write the entry in the very words a CHANGELOG bullet has today (`- **...**` or a paragraph, any number of lines, non-empty UTF-8, no heading); the directory holds only its README and fragments. A PR changing `src/`, `mcp/src/`, `tests/e2e/` or `Cargo.toml` adds a fragment or carries `no-changelog`, meaning tests only, docs only, a re-record, or CI wiring. Adding a label does not trigger CI (`pull_request` runs on opened, synchronize and reopened); a `no-changelog` label added after a failure counts when the ratchet job is re-run. The release PR assembles the entries as [changelog.d/README.md](../../changelog.d/README.md) describes; never a line in CHANGELOG.md's Unreleased.
13. **The harness's browser (#355, #362, #366).** One standing browsers folder per host, which `tests/e2e/lib/browsers.js` resolves in order: a non-empty `PLAYWRIGHT_BROWSERS_PATH` (the Studio Mac's captain exports `/Volumes/Lanes/targets/bsv-wallet-cli-playwright`, the program's standing folder there); else the standing checkout's `.cca/pw-browsers` (the parent of `git rev-parse --git-common-dir`: on the box `~/bsv/bsv-wallet-cli/.cca/pw-browsers`, shared by every worktree); else, without git, the worktree's own `tests/e2e/.browsers`. The run's check line names the folder, why and Node. The install runs once per host by the harness's own step, `node tests/e2e/install-browsers.js` after `npm ci` in `tests/e2e`, never by hand and never a zip unpacked; a lane whose check line passes does not reinstall. `tests/e2e/package.json` declares the proven Node majors as `20 || 22 || 24`: the Studio Mac's gate uses 20.19.5, the box's install uses 22.23.3, and CI uses 24. Select one with `nvm use 22` (or put an installed `node@22` on `PATH`). The box defaults to 26.9.0, under which Playwright 1.58.2's zip extractor never finishes after "extracting archive". The step refuses any Node outside the range before checking the local binary or downloading; running under 26 remains allowed. Change the range only with a Playwright bump whose extractor is re-tested on each host (#366). Keep `PLAYWRIGHT_SKIP_BROWSER_GC=1` set (the step sets it too); never install into or collect the shared browser cache. The harness checks the pinned headless executable before starting any wallet or asking the funder.
